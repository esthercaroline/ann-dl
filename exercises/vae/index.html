    VAE — Variational Autoencoders

    Approach. Both exercises share one hand-written VAE in vae.py: encoder \(784 \to 512 \to 256\) (ReLU), heads for \(\boldsymbol{\mu}\) and \(\log\boldsymbol{\sigma}^2\), decoder \(d \to 256 \to 512 \to 784\) (ReLU, sigmoid), the reparameterization \(z = \mu + \sigma \odot \varepsilon\), and the loss with BCE summed over pixels plus the closed-form KL. Exercise 1 uses \(d = 16\); Exercise 2 only changes \(d\) to \(2\). Seeds, split, \(\beta = 1\), Adam (\(10^{-3}\)), batch size 128 and 20 epochs are fixed as in the statement.

    Technical rules used throughout: torch.manual_seed(42) before each model; the split generator torch.Generator().manual_seed(42); both loss terms logged separately in nats per image; the test set used only for the final numbers.

    Exercise 1 — A real VAE on MNIST

    A — Load and split the data

    MNIST from torchvision with transforms.ToTensor() (pixels in \([0, 1]\)), flattened to 784-vectors. The 60 000 training images are split into 50 000 / 10 000 with the required generator; the 10 000 official test images are the test set and are not touched until the final evaluation.

    from torch.utils.data import random_split

train_full = datasets.MNIST("data", train=True, download=True,
                            transform=transforms.ToTensor())
test = datasets.MNIST("data", train=False, download=True,
                      transform=transforms.ToTensor())
train, val = random_split(train_full, [50_000, 10_000],
                          generator=torch.Generator().manual_seed(42))

    B — Build the model

    """Variational Autoencoder for MNIST.

Architecture (Exercise 1 / 2):
  Encoder: 784 -> 512 -> 256 (ReLU), then two heads 256 -> d for mu and log_var.
  Decoder: d -> 256 -> 512 -> 784 (ReLU on hidden, sigmoid on output).

The reparameterization, BCE reconstruction (summed over pixels), and the
closed-form KL are written by hand — no library VAE / kl_divergence helpers.
"""

from __future__ import annotations

from dataclasses import dataclass, field

import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.utils.data import DataLoader, Dataset


class VAE(nn.Module):
    """Fully-connected VAE with Bernoulli decoder (sigmoid + BCE)."""

    def __init__(self, latent_dim: int = 16):
        super().__init__()
        self.latent_dim = latent_dim

        self.enc = nn.Sequential(
            nn.Linear(784, 512),
            nn.ReLU(),
            nn.Linear(512, 256),
            nn.ReLU(),
        )
        self.fc_mu = nn.Linear(256, latent_dim)
        self.fc_log_var = nn.Linear(256, latent_dim)  # predicts log sigma^2

        self.dec = nn.Sequential(
            nn.Linear(latent_dim, 256),
            nn.ReLU(),
            nn.Linear(256, 512),
            nn.ReLU(),
            nn.Linear(512, 784),
            nn.Sigmoid(),
        )

    def encode(self, x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
        h = self.enc(x)
        return self.fc_mu(h), self.fc_log_var(h)

    def reparameterize(self, mu: torch.Tensor, log_var: torch.Tensor) -> torch.Tensor:
        # z = mu + sigma * eps, with eps ~ N(0, I); log_var = log(sigma^2)
        std = torch.exp(0.5 * log_var)
        eps = torch.randn_like(std)
        return mu + std * eps

    def decode(self, z: torch.Tensor) -> torch.Tensor:
        return self.dec(z)

    def forward(self, x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
        mu, log_var = self.encode(x)
        z = self.reparameterize(mu, log_var)
        return self.decode(z), mu, log_var


def vae_loss(
    x_hat: torch.Tensor,
    x: torch.Tensor,
    mu: torch.Tensor,
    log_var: torch.Tensor,
    beta: float = 1.0,
) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
    """Return (total, reconstruction, KL), each averaged over the batch (nats / image).

    Reconstruction: BCE summed over the 784 pixels (Bernoulli ELBO term).
    KL: closed-form 1/2 * sum_i (mu_i^2 + sigma_i^2 - 1 - log sigma_i^2).
    """
    batch = x.size(0)
    # reduction="sum" keeps the pixel sum; divide by batch so the KL is not
    # secretly scaled by beta ≈ 784 (which reduction="mean" would do).
    recon = F.binary_cross_entropy(x_hat, x, reduction="sum") / batch
    # KL(q(z|x) || N(0,I)) = 1/2 * sum (mu^2 + sigma^2 - 1 - log sigma^2)
    kl = 0.5 * torch.sum(mu.pow(2) + log_var.exp() - 1.0 - log_var) / batch
    total = recon + beta * kl
    return total, recon, kl


@dataclass
class History:
    train_recon: list[float] = field(default_factory=list)
    train_kl: list[float] = field(default_factory=list)
    val_recon: list[float] = field(default_factory=list)
    val_kl: list[float] = field(default_factory=list)


def _flatten_batch(batch) -> torch.Tensor:
    x, _ = batch
    return x.view(x.size(0), -1)


@torch.no_grad()
def evaluate(
    model: VAE,
    loader: DataLoader,
    device: torch.device,
    beta: float = 1.0,
) -> tuple[float, float]:
    """Average reconstruction and KL (nats / image) over ``loader``."""
    model.eval()
    recon_sum = 0.0
    kl_sum = 0.0
    n = 0
    for batch in loader:
        x = _flatten_batch(batch).to(device)
        x_hat, mu, log_var = model(x)
        _, recon, kl = vae_loss(x_hat, x, mu, log_var, beta=beta)
        recon_sum += recon.item() * x.size(0)
        kl_sum += kl.item() * x.size(0)
        n += x.size(0)
    return recon_sum / n, kl_sum / n


def train_vae(
    model: VAE,
    train_set: Dataset,
    val_set: Dataset,
    *,
    epochs: int = 20,
    batch_size: int = 128,
    lr: float = 1e-3,
    beta: float = 1.0,
    device: torch.device | None = None,
) -> History:
    """Adam training; logs reconstruction and KL on train (epoch avg) and val."""
    device = device or torch.device("cpu")
    model = model.to(device)
    opt = torch.optim.Adam(model.parameters(), lr=lr)

    train_loader = DataLoader(train_set, batch_size=batch_size, shuffle=True)
    val_loader = DataLoader(val_set, batch_size=batch_size, shuffle=False)

    hist = History()
    for epoch in range(1, epochs + 1):
        model.train()
        recon_sum = 0.0
        kl_sum = 0.0
        n = 0
        for batch in train_loader:
            x = _flatten_batch(batch).to(device)
            opt.zero_grad()
            x_hat, mu, log_var = model(x)
            total, recon, kl = vae_loss(x_hat, x, mu, log_var, beta=beta)
            total.backward()
            opt.step()
            recon_sum += recon.item() * x.size(0)
            kl_sum += kl.item() * x.size(0)
            n += x.size(0)

        train_recon = recon_sum / n
        train_kl = kl_sum / n
        val_recon, val_kl = evaluate(model, val_loader, device, beta=beta)

        hist.train_recon.append(train_recon)
        hist.train_kl.append(train_kl)
        hist.val_recon.append(val_recon)
        hist.val_kl.append(val_kl)

        print(
            f"epoch {epoch:02d}/{epochs}  "
            f"train recon={train_recon:.2f} kl={train_kl:.2f}  "
            f"val recon={val_recon:.2f} kl={val_kl:.2f}"
        )

    return hist

    The reconstruction term is F.binary_cross_entropy(..., reduction="sum") / batch_size, so it is summed over the 784 pixels and averaged over images. The KL is the closed form \(\tfrac{1}{2}\sum_i(\mu_i^2 + \sigma_i^2 - 1 - \log\sigma_i^2)\), also averaged over the batch — no torch.distributions.kl_divergence.

    C — Train

    Adam, learning rate \(10^{-3}\), batch size 128, 20 epochs, \(\beta = 1\). After each epoch the reconstruction and KL are recorded on the training set (epoch average) and on the validation set.

    Test numbers (\(d = 16\)): reconstruction 79.98 nats/image, KL 20.86 nats/image, negative ELBO 100.84 nats/image. That sits next to the reference region of roughly 81 and 20. Validation KL rises from 13.45 at epoch 1 to 20.82 at epoch 20.

    D — Reconstructions and samples

    Figure 2 reconstructs the first test image of each digit \(0\)–\(9\) by decoding \(\boldsymbol{\mu}\) (no sampling of \(z\)). Figure 3 decodes an \(8 \times 8\) grid of \(z \sim \mathcal{N}(0, I)\) drawn after torch.manual_seed(0).

    E — Analysis

    1. Why the KL rises while the total loss falls. Early on, a cheap way to keep the KL near zero is to push every \(q(z \mid x)\) toward the prior and ignore the latent code — but then reconstruction stays high. Moving \(\boldsymbol{\mu}\) and \(\boldsymbol{\sigma}\) away from \((0, 1)\) costs KL, yet it buys a larger drop in the BCE term because the decoder can finally use \(z\) to explain which digit (and which style) \(x\) is. Figure 1 shows that trade: reconstruction falls by tens of nats while the KL climbs from about 13 to 21. The optimizer pays more KL because each nat of KL buys more than one nat of reconstruction.

    2. Why Figure 3 looks worse than Figure 2 (two reasons).

    • Where the prior samples land. Reconstructions in Figure 2 use \(\boldsymbol{\mu}(x)\) for real test images, so \(z\) sits where the aggregate encoder posterior actually puts mass. Prior samples \(z \sim \mathcal{N}(0, I)\) can land in low-density gaps between digit clusters (or in the tails). The decoder has never been asked to decode those points from a real \(x\), so the images look wrong or like no digit at all.

    • What the decoder outputs for a given \(z\). The sigmoid decoder models each pixel as a Bernoulli probability — the mean of \(p(x \mid z)\). When several digit shapes are compatible with the same \(z\), that mean averages them, which is exactly the blur discussed in the lecture. Figure 2 already shows some softness; prior samples amplify it because \(z\) is less committed to one mode.

    3. Why decode \(\boldsymbol{\mu}\) in Figure 2. The goal is to show how well the model reconstructs a given test image. Decoding \(\boldsymbol{\mu}\) is the deterministic mean of \(q(z \mid x)\) and removes sampling noise. A random \(z \sim q(z \mid x)\) would add variance that has nothing to do with whether the encoder–decoder pair is faithful, and would make the comparison across digits unfair.

    C — The decoded plane

    The \(15 \times 15\) grid uses \(z = \Phi^{-1}(q)\) with \(q\) evenly spaced in \([0.05, 0.95]\) (scipy.stats.norm.ppf). That spacing gives every cell the same prior mass under \(\mathcal{N}(0, I)\), because equal steps in the CDF are equal probability under the prior — unlike a linear grid, which over-samples the tails.

    D — Interpolation

    Test indices 4 (digit 4) and 7 (digit 9). Top row: pixel-space blend \((1-t)\,x_a + t\,x_b\). Bottom row: decode \((1-t)\,\boldsymbol{\mu}_a + t\,\boldsymbol{\mu}_b\) with the \(d = 16\) model from Exercise 1.

    E — Analysis

    1. Which digits overlap, and what do the in-betweens look like? In Figure 4 the clearest overlaps are 4 with 9 (right side) and the 3 / 5 / 8 pile near the origin; 7 also sits next to 9. The same transitions appear in Figure 5: moving through the 4–9 region produces looped shapes that could be either digit, and the 3–5–8 region produces soft S- and B-like morphs rather than a clean member of one class.

    2. What does \(d = 2\) force the model to throw away? Two numbers cannot encode within-class style — stroke thickness, slant, openness of loops — alongside class identity. Evidence in Figure 5: each cell shows a generic prototype of a digit, not the variety of the test set. That missing detail is exactly why reconstruction jumps from 79.98 (\(d = 16\)) to 133.86 (\(d = 2\)).

    3. Which row of Figure 6 looks like digits, and why? The latent row. The decoder was trained only on points that come from the encoder, so the segment between \(\boldsymbol{\mu}_a\) and \(\boldsymbol{\mu}_b\) stays near the learned manifold and decodes as a single evolving digit. The pixel row is a convex combination of two unrelated 784-vectors: in the middle both ink patterns are half-on, which is a double exposure, not a digit the model (or a person) would write.
